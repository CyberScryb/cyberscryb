Why I Built CyberScryb: A Privacy-First Dev Tools Story

By CyberScryb Team · March 15, 2026 · 6 min read

I got tired. That is the honest, unromantic start to this story. I got tired of opening a "free JSON formatter" and being asked to create an account. Tired of pasting a password into a checker and wondering whether it was quietly logged somewhere in Virginia. Tired of dev tool websites where the tool itself was a loss-leader for a $29/month SaaS pitch.

So one weekend in late 2025, I opened a blank repo and started building the site I wished already existed. That site became CyberScryb.

The three rules I wrote on a sticky note

Before writing a single line of code, I wrote three rules on a yellow sticky note and pinned it above my monitor. Every feature, every decision, every line of CSS has to pass all three.

  1. Nothing leaves the browser unless it has to. JSON, passwords, regex, Markdown — all of it runs locally in your browser tab.
  2. No signups. Ever. Not for "pro features." Not for "unlimited use." Nothing.
  3. Fast or dead. If a page takes more than 2 seconds to become interactive on a mid-range phone, it gets stripped down until it does.

What was broken about existing tools

If you have ever searched "online JSON formatter" you know the pattern. The first five results are identical-looking sites stuffed with ads, dark patterns, and a sidebar menu that tries to redirect you to their "premium validator."

The deeper problem is that these sites have the wrong business model. When a free tool's goal is to convert you into a paying customer for a product you did not ask for, every design decision gets distorted. Features you need get hidden. Features you do not need get pushed. And almost nobody asks the one question that matters: what is actually happening to the data you paste in?

The password checker problem

Here is a concrete example. I once audited a popular "password strength checker" (I will not name it — it is still online). It claimed to work offline. It did not. The moment you typed a character, the full password was sent to an analytics endpoint as a query parameter. Not hashed. Not truncated. In the query string, where every load balancer and server log in the pipeline would capture it.

That is the kind of thing that made me obsessive about building tools that genuinely run client-side. The CyberScryb Password Checker never sends your password anywhere. The entropy math, the pattern detection, the crack-time estimates — all of it happens in JavaScript that runs inside your own browser. If you disconnect from Wi-Fi, it still works.

The quiet pleasure of building what you want to use

The first tool I finished was the JSON ↔ CSV converter. I had a specific use case: a CSV export from a client's database that had nested JSON blobs inside one of the columns. Every tool I tried either choked on the file size or mangled the nested objects. So I built our own converter that could flatten nested paths, handle 50,000+ rows in the browser, and export clean output.

Next came the AI Humanizer. I had been using ChatGPT for rough drafts and kept noticing the same "AI tells" — the em-dashes, the perfectly balanced three-item lists, the phrase "it is important to note." Editors could smell it from a mile away. I wanted a tool that would rewrite AI text in a way that did not read like AI, without slipping into the awkward thesaurus-spam territory of the big-name humanizer services. So I built it.

Why this has to stay free

People ask me: "If you are not charging, how does this site survive?" The answer is boring. CyberScryb runs on a dollar-per-day budget on a cheap VPS, plus modest AdSense revenue on the pages where it does not interrupt the work. That covers hosting, a domain, and a coffee-equivalent amount of time each month.

If it grows — great. If it does not — also fine. The goal was never to build a unicorn. The goal was to have a tool belt I trust, and to let other developers use it too, without having to read a privacy policy to use a regex tester.

What is next

The roadmap is short and honest. More tools where I keep reinventing the wheel myself: a better diff viewer, a cron expression builder (already done), a color palette generator that respects WCAG contrast, a faster Markdown to HTML converter with preview. A few AI-assisted tools where the server-side calls are necessary — but even there, inputs are never logged, outputs are never stored, and the whole pipeline is designed so a breach would leak nothing interesting.

The kind of feedback that matters

If you use a CyberScryb tool and it fails on your data, I want to hear about it. Not "your UI is ugly" (I know) — but "I pasted this 400MB JSON and it crashed." That is the feedback that makes the tools better. You can reach me through the contact page, and the response is almost always a real human within 24 hours.

The invitation

If you are reading this as a developer: use the tools, tell me when they break, and spread the word if you think they deserve it. If you are reading this as someone thinking about building your own free tools site: do it. The web needs more small sites built by one or two people who actually care. Not another venture-backed "AI productivity platform." Not another newsletter funnel. Just real tools that work.

In the meantime, start with the ones that solve a problem you actually have today. Try the AI Humanizer free, or pick whatever is at the top of the tools page. No signup, no trial, no email capture. Just open it and use it.
